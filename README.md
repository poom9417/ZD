# ลูกหนี้ ZD (AR Dashboard)

เว็บแสดงลูกหนี้ค่ารักษาพยาบาลจากไฟล์ ZD ที่วิเคราะห์แล้ว มี 2 หน้า สลับด้วยแถบเมนูด้านบน (เก็บหน้าไว้ใน URL hash)

| หน้า | hash | ไฟล์ |
|---|---|---|
| ตารางหลัก (pivot: สิทธิ › กลุ่มลูกหนี้ › หน่วยงาน × ช่วงอายุ) | `#pivot` (หน้าแรก) | `src/pages/PivotPage.tsx` |
| Dashboard อายุลูกหนี้ ZD | `#dashboard` | `src/pages/DashboardPage.tsx` |

## โครงสร้าง

```
scripts/build_data.py     อ่าน .xlsx (ชีต data) → src/data/zd-records.json
src/
  main.tsx, App.tsx
  components/             AppLayout (สลับหน้า), Navbar, NavMenu, PivotTable, StatCards, AgingBar, ...
  pages/                  PivotPage, DashboardPage
  lib/                    buckets (ช่วงอายุ), pivot (สร้างตาราง), arSummary (คำนวณ Dashboard), format
  data/zd-records.json    ข้อมูลสรุป (สร้างด้วยสคริปต์ ไม่ต้องแก้มือ)
  styles/                 theme, base, components/*.css
```

ตัวเลขทุกจุดคำนวณจาก `zd-records.json` ผ่าน `lib/` ไม่มีตัวเลขฝังในหน้า

## รันในเครื่อง

ต้องใช้ Node.js 18 ขึ้นไป

```bash
npm install
npm run dev
npm run build     # tsc + vite build
```

## เปลี่ยนข้อมูลเป็นไฟล์ ZD ใหม่

ต้องมี Python 3 กับ `pandas`, `openpyxl`

```bash
npm run data -- path/to/ZDddmmyyyy_analyzed.xlsx
```

สคริปต์ใช้คอลัมน์ `ช่วงอายุลูกหนี้-` ซึ่งแยกค้างเกิน 90 วันเป็น (4) ปีงบ 2026, (5) ปีงบ 2025, (6) ปีงบ 2024 และก่อนหน้า ส่วนวันที่รายงานอ่านจากคอลัมน์ `Adateasat(วันที่รายงาน)`

## Deploy

เป็นเว็บ static: push ขึ้น `main` แล้วเชื่อม Vercel (Framework: Vite) หรือ Render Static Site (Build: `npm install && npm run build`, Publish: `dist`) `vercel.json` ตั้ง security headers ไว้


## ปรับปรุง 24 พฤศจิกายน 2026: ตารางเต็มหน้าและอัปโหลดไฟล์

- ขยายเนื้อหาเต็มความกว้างหน้าจอ ตรึงหัวตาราง คอลัมน์ชื่อ และแถวรวมทั้งหมด พร้อมเลื่อนตารางภายในพื้นที่หน้าจอ
- ปุ่ม **อัปโหลดไฟล์** อยู่ด้านบนทั้งสองหน้า รองรับ Excel `.xlsx`/`.xls`, CSV และ JSON รูปแบบ `zd-records.json` ขนาดไม่เกิน 25 MB
- Excel จะเลือกชีต `data` ก่อน หากไม่มีจะเลือกชีตแรก สามารถเปลี่ยนชีตเองได้
- แสดงจำนวนรายการ ยอดรวม และวันที่รายงานก่อนกด **สร้าง Dashboard จากไฟล์นี้** จากนั้นตารางและ Dashboard ใช้ข้อมูลชุดเดียวกัน
- เปลี่ยนวันที่รายงานได้ในช่องวันที่ โดยมีผลต่อวันที่แสดงในรายงานเท่านั้น ช่วงอายุใช้ค่าจากไฟล์ ไม่คำนวณอายุใหม่
- ตรวจคอลัมน์และค่าข้อมูลก่อนแทนที่ข้อมูลเดิม หากไฟล์ผิดจะแสดงข้อผิดพลาด และยังใช้ข้อมูลเดิมได้
- ประมวลผลบนเบราว์เซอร์ ไม่มีการส่งไฟล์ขึ้นเซิร์ฟเวอร์ ไม่บันทึกถาวร เมื่อรีเฟรชจะกลับไปใช้ข้อมูลที่มากับโปรเจกต์

### รูปแบบ Excel / CSV

ต้องเป็นไฟล์ ZD ที่วิเคราะห์และจัดประเภทแล้ว **ยังไม่จัดประเภทจาก ZD ดิบให้อัตโนมัติ** เพราะไฟล์ดิบอาจไม่มีข้อมูลสิทธิ กลุ่มลูกหนี้ และช่วงอายุที่กติกาสรุปเดิมต้องใช้

| คอลัมน์ | การใช้งาน |
|---|---|
| `สิทธิ` | ต้องมีคอลัมน์ ค่าว่างใช้ `(ไม่ระบุสิทธิ)` |
| `กลุ่มลูกหนี้` | ต้องมีคอลัมน์ ค่าว่างใช้ `(ไม่ระบุกลุ่ม)` |
| `Name` | ต้องมีคอลัมน์ ค่าว่างใช้ `(ไม่ระบุ)` |
| `ช่วงอายุลูกหนี้-` | ต้องมีคอลัมน์ ค่า `(0)` ถึง `(6)` พร้อมข้อความต่อท้าย หรือเลข 0–6; ว่างเป็น `(blank)` |
| `FiscalYear` | ต้องมีคอลัมน์และปี 4 หลัก รองรับ ค.ศ./พ.ศ. (พ.ศ. แปลงเป็น ค.ศ.) |
| `Amt in loc.cur.` | ต้องมีคอลัมน์และตัวเลข รองรับติดลบ คั่นหลักพัน และวงเล็บยอดลบ เช่น `(100.25)` |
| `Ref.key 1` | ไม่บังคับ รองรับ OPD/IPD ว่างใช้ OPD ตามกติกาเดิม |
| `Adateasat(วันที่รายงาน)` | ไม่บังคับ ใช้วันที่ล่าสุดที่อ่านได้ รองรับวันที่ Excel, dd/mm/yyyy, dd.mm.yyyy และ yyyy-mm-dd; หากไม่พบให้เลือกวันที่เอง หรือแสดง “ไม่ระบุ” |

CSV รองรับ UTF-8, UTF-16 ที่มี BOM และ Windows-874 (กรณีตรวจพบ UTF-8 ที่อ่านไม่ได้) ช่วงอายุ `(4)`–`(6)` รวมเป็นค้างเกิน 90 วันใน Dashboard เหมือนเดิม โดยไม่เดาปีงบใหม่จากวันที่ที่เลือก

มีไฟล์ตัวอย่างข้อมูลสมมติใน `samples/ZD_upload_example.csv` จำนวน 3 รายการ ยอดสุทธิ 2,900,000 บาท สำหรับลองอัปโหลด
